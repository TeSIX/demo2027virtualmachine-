## Исправлено по итогам аудита (этот коммит)

### Критичные

1. **`tools/import-users.sh`: `--userou` портился выводом `samba-tool ou create`.**
   Stdout создания OU попадал в `$(ensure_ou)` → `--userou="Created OU …OU=OfficeHQ"`.
   Подтверждено stub-тестом. Теперь весь вывод `ou create` уходит в stderr.
2. **`tools/import-users.sh`: терялась последняя строка CSV** без завершающего перевода
   строки (подтверждено: пользователь из последней строки не создавался) и **падал CSV
   с BOM** (файл из Excel). Добавлены обработка BOM/пробелов и подсчёт ошибок с
   ненулевым кодом выхода при неудачах (раньше скрипт мог завершиться «успешно»
   при проваленном импорте — цикл был пайплайном в сабшелл).
3. **Пустая колонка `ou`** создавала фиктивную `OU=Users` рядом со встроенным
   `CN=Users`. Теперь пользователь без OU создаётся без `--userou`.
4. **`write_nat`: DNAT модуля 2 не применялся.** `systemctl enable --now` не
   перезапускает уже работающую службу, поэтому поверх NAT модуля 1 правила
   prerouting не подхватывались (а `nft -f` вручную дублировал бы правила).
   Добавлен `systemctl restart exam-nat`.
5. **`eth_iface`: старый шлюз по умолчанию оставался** на интерфейсах без маршрута
   (trunk ens37 HQ-RTR, линки BR): `ipv4route` не очищался, хотя материал прямо
   требует удалять старый default route. Подтверждено тестом в namespace.
6. **Порядок запуска dnsmasq в модуле 1 (HQ-RTR и HQ-SRV).** Служба с
   `bind-interfaces` стартовала **до** `systemctl restart network`: на первом
   запуске VLAN/адрес ещё не подняты → dnsmasq падает → `set -e` обрывает скрипт
   **до** применения сети. Сеть теперь применяется до запуска DNS/DHCP, плюс
   добавлен `restart` для перечитывания конфига при повторных запусках.
7. **Модуль 2, HQ-CLI: автоматический reboot посреди скрипта.** При `--yes`
   `confirm()` сам «соглашался» на перезагрузку после ввода в домен — шаги после
   (sudoers, NFS, браузер) не выполнялись и не возобновлялись. Автоперезагрузка
   убрана, скрипт просит перезагрузить ВМ вручную и повторить запуск.

### Средние

8. **`mdadm --detail --scan > /etc/mdadm.conf` стирал существующий конфиг.**
   Теперь строки ARRAY добавляются через `ensure_line` с резервной копией.
9. **Docker (BR-SRV): в `/opt/testapp` копировался весь каталог ISO**, если
   compose лежал в его корне (включая tar-образы). Теперь копируются compose
   и соседние `.env*`; связанные конфиги/данные из каталога compose на ISO
   всё равно проверьте вручную (см. риски).
10. **Сертификат (модуль 3) перегенерировался при каждом запуске**, создавая
    новый CA и ломая доверие уже настроенных ISP/HQ-CLI. Добавлена проверка
    существования `sites.crt/sites.key`.
11. **ISP (модуль 3): битый vhost оставался включённым.** Если сертификата ещё
    нет, `apachectl -t` падал, но сайт уже был `a2ensite`-нут — Apache не поднялся
    бы после перезагрузки. Теперь при провале `-t` сайт отключается обратно
    (`a2dissite`), скрипт завершается с понятной ошибкой.
12. **Samba (модуль 2): `samba-tool group show`** заменён на `group list | grep` —
    если подкоманды `show` нет в установленной версии, старый вариант пытался
    создать дубликат группы и обрывал скрипт.

### Найдено при первом запуске на живой ВМ (HQ-RTR)

13. **Прямой запуск фрагмента `bash scripts/m1/hq-rtr.sh`** давал
    `command not found` на каждой функции (`step`, `eth_iface`, `apt_install`…):
    фрагменты `scripts/m*/` не самостоятельны, `scripts/lib/common.sh` подключает
    только диспетчер `demo2027.sh`. Из-за этого, в частности, не поставился
    dnsmasq (`Failed to restart dnsmasq.service: Unit … not found` — следствие,
    не причина). Исправлено: каждый фрагмент при прямом запуске сам делает
    `exec demo2027.sh <роль> <модуль>` (роль/модуль — по имени файла,
    `DEMO2027_DISPATCHED` ставится диспетчером), а в README добавлен запрет
    запускать фрагменты в обход диспетчера. Проверено прямым запуском и из
    чужого каталога: rc=0, ни одного `command not found`. После такого
    неудачного запуска на ВМ перед повторным прогоном ничего чистить не нужно —
    просто запустить правильно через диспетчер.

14. **Имена интерфейсов не совпали с материалом (BR-RTR).** Материал называет
    адаптеры `ens33/ens37/ens38`, а гипервизор на BR-RTR дал второй адаптер как
    **`ens34`** (`enp2s2`). Скрипт создавал etcnet-конфиг для несуществующего
    `ens37`, реальный `ens34` оставался без `192.168.10.0/31`, и BR-FW получал
    `Destination Host Unreachable` при обращении к шлюзу `192.168.10.0` — хотя на
    самом BR-FW маршруты были верны. Исправлено: `IF1/IF2/IF3` определяются по
    порядку физических интерфейсов (`/sys/class/net`, только реальные устройства),
    ручной override — `IFACE1/IFACE2/IFACE3` в `config.env`. Заодно заменены все
    жёсткие `ens33/ens37/ens38` в etcnet, VLAN HOST, GRE, NAT/DNAT (oifname/iifname),
    FRR (`interface …`, `no passive-interface …`), dnsmasq, sysctl rp_filter и HQ-SW.
    Проверено на подделанном `/sys` (`ens33`+`ens34` → IF2=ens34, override работает).
    На уже пострадавшей ВМ лечение: `git pull --ff-only`, повторный запуск роли —
    скрипт создаст конфиг правильного интерфейса; лишний каталог
    `/etc/net/ifaces/ens37` можно удалить, если такого интерфейса на ВМ нет.


15. **На BR-RTR оказался `net.ipv4.ip_forward = 0` при живом NAT и маршрутах**
    (найдено на живой ВМ). Файл `/etc/sysctl.d/90-exam-router.conf` создавался и
    `sysctl --system` вызывался, но перезапуск сети в конце роли (`apply_network`)
    сбрасывал значение — в итоге транзит BR-FW -> ISP не работал при полностью
    исправных NAT/OSPF/GRE. Исправлено: `apply_network` повторно применяет
    `sysctl --system` после рестарта сети и печатает итоговый `ip_forward`, а
    `enable_forwarding` дополнительно делает `sysctl -w net.ipv4.ip_forward=1` и
    предупреждает, если значение всё равно перекрыто (тогда искать
    `grep -R ip_forward /etc/sysctl.conf /etc/sysctl.d/` — /etc/sysctl.conf может
    читаться последним и задавать 0).


16. **Усиление по итогам пп. 13–15 (все маршрутизаторы сразу).**
    `enable_forwarding` теперь: пишет rp_filter только для существующих
    интерфейсов; приводит активную строку `net.ipv4.ip_forward` в
    `/etc/sysctl.conf` к `1` (она могла перекрывать sysctl.d после перезагрузки);
    не падает от ошибок `sysctl --system`. `apply_network` после рестарта сети
    повторно применяет sysctl и форсит `ip_forward=1` при наличии нашего конфига,
    плюс предупреждает об оставшихся конфигах несуществующих интерфейсов
    (/etc/net/ifaces/ens37 при реальном ens34) и о «хвостах» `interface ens37`
    в сохранённом frr.conf. Регрессия от `[ -e ] && printf` в цикле под
    `set -e/pipefail` (rc=1 на ВМ с двумя адаптерами) найдена повторным
    dry-run всех 32 комбинаций и исправлена на `if`.

## Что может пойти не так (не исправлено, знать перед запуском)

### Общие / архитектурные

- **`set -e` без отката.** Любая необёрнутая команда (vtysh, `sshd -t`,
  `fail2ban-client -t`, `mariadb`, `system-auth`, restic `init`) обрывает скрипт
  посреди роли: часть конфигов уже записана, сеть, возможно, ещё не применена
  (или уже применена). Транзакционности нет; восстановление — из
  `/root/demo2027-backup/<дата>/` вручную. После обрыва просто исправьте причину
  и запустите роль повторно — скрипты в основном идемпотентны.
- **`systemctl restart network` рвёт SSH.** Если новый etcnet-конфиг окажется
  битым (опечатка в адресе, не тот интерфейс), ВМ станет недоступна по сети —
  только консоль гипервизора. Поэтому: сначала `--dry-run`, работать из консоли.
- **Нет префлайт-проверок.** Скрипты не проверяют: существование
  `ens33/ens37/ens38` (`ip link`), занятость портов 53/2027/8080, активность
  firewalld (правила nftables из скриптов будут соседствовать/конфликтовать),
  живость Samba DC, состав Additional.iso. Ошибки проявятся по ходу, а не заранее.
- **Роли без скрипта модуля завершаются с кодом 0** (например, `br-fw 2`) —
  для ручного запуска это просто предупреждение, но в автоматике даст ложное
  «успешно». То же: `./demo2027.sh` без аргументов печатает usage и выходит с 0.
- **Если `config.env` отсутствует**, предупреждение обещает «значения из
  примера», но файл на самом деле не подгружается: сработают лишь встроенные
  fallback-и (`DOMAIN`, `TIMEZONE`, часть паролей `P@ssw0rd`). Для
  `sshuser`/`net_admin` пароль тогда **не будет задан** — только предупреждение.
- **Пароли видны в списке процессов**: `samba-tool user create … 'P@ssw0rd'`,
  `htpasswd -b`, `system-auth … 'пароль'` передают секрет аргументом командной
  строки (`ps aux` на время выполнения). Для учебного стенда приемлемо,
  для боевого — нет.
- **Резервные копии в пределах одной секунды перезаписывают друг друга**
  (метка времени — до секунд) при нескольких записях одного файла подряд.

### Модуль 1 (сеть)

- **Имена интерфейсов захардкожены** (`ens33/ens37/ens38`). На ВМ с другой
  схемой именования (enp0s*, ens192…) скрипты создадут конфиги несуществующих
  интерфейсов и применят пустую сеть.
- **`rp_filter` выставляется только для ens33/37/38**, но не для `gre1`/VLAN —
  при асимметричной маршрутизации через GRE возможны отбрасывания пакетов.
  GRE (протокол 47) и OSPF (89) явно разрешены только политикой accept цепочек
  NAT; при включённом firewalld с DROP их нужно открывать отдельно.
- **FRR через интерактивный `vtysh` со stdin.** Если версия FRR поведёт себя
  иначе (пауза, запрос подтверждения `write memory`), скрипт может зависнуть
  или оборваться до `apply_network`. На стенде один раз выполнить внимательно.
- **UID 2027.** Если UID занят другим пользователем или `sshuser` уже существует
  с другим UID, скрипт это проигнорирует (для отчёта может не зачесться) либо
  `useradd` упадёт и оборвёт роль до применения сети.
- **BR-SRV сразу получает `nameserver 192.168.100.2`**, хотя DNS на HQ-SRV может
  быть ещё не поднят (если порядок ролей нарушен) — временная потеря резолва.
- **HQ-SW (Linux-мост)** не отключает управление своими ens33/37/38 со стороны
  etcnet: после перезагрузки etcnet и `hq-switch.service` могут конфликтовать
  за интерфейсы. Плюс не заданы STP/ageing — на стенде с петлёй будет шторм.

### Модуль 2 (администрирование)

- **RAID: главный остаточный риск.** Скрипт доверяет `RAID_DISKS` из конфига:
  не проверяет, что диски существуют, не смонтированы и не являются системными.
  Ошибка в конфиге + `RAID_CONFIRM=YES` = уничтоженные данные. Повторный запуск
  при существующем `/dev/md0` падает (`mdadm --create` не идемпотентен).
- **DNS для домена не донастраивается.** Материал требует условную пересылку
  зоны `au-team.irpo` с HQ-SRV на BR-SRV (SRV-записи AD), иначе HQ-CLI не найдёт
  контроллер. В скриптах dnsmasq HQ-SRV остаётся с `local=/au-team.irpo/` из
  модуля 1 — **перед вводом HQ-CLI в домен это нужно поправить вручную**
  (замена `local=` на `server=/au-team.irpo/192.168.30.2`, рестарт dnsmasq).
- **Ввод в домен**: NetBIOS-имя `AU-TEAM` захардкожено (на стенде может быть
  другое — смотреть `testparm -s`); `system-auth` при недоступном DC оборвёт
  скрипт до шагов sudoers/NFS/браузера; проверка `sudo -l -U hquser1@…` до
  перезагрузки/синхронизации SSSD закономерно может не увидеть пользователя.
- **sudoers для группы hq**: пути `/usr/bin/cat|grep|id` захардкожены; если в
  ALT бинарники лежат в `/bin`, правило синтаксически валидно, но работать не
  будет. Проверять `command -v cat grep id`.
- **Ansible**: `ssh-copy-id` выполняется вручную (пароли, host key), скрипт
  только печатает команды. Инвентарь жёстко предполагает SSH маршрутизаторов
  на порту 22 — если на готовом стенде там 2027, pong не будет.
- **Docker testapp зависит от содержимого ISO**: теги образов, внутренние порты
  и переменные берутся из выданного compose; скрипт не правит `image:` и порты
  под `8080:80` — если в compose публикации 8080 нет, проверка `curl :8080`
  честно упадёт. Имя пакета Compose (`docker-compose-v2` vs `docker-compose`)
  и сервиса (`docker-engine`) — как в ALT p11 на момент написания; проверить
  `apt-cache search docker`.
- **Apache/PHP**: версия PHP определяется поиском по apt (`phpX.Y`), имя модуля
  для `a2enmod` подбирается из двух вариантов; если в ветке p11 структура
  другая, сайт включится без PHP и начнёт отдавать исходники `index.php`
  (скрипт это не детектирует). Аналогично пакет `mariadb` и socket-аутентификация
  root приняты по материалу.
- **NFS**: `anonuid/anongid=65534` захардкожены; по материалу нужно свериться
  с `getent passwd 65534` на конкретном стенде ALT. Экспорт при этом всё равно
  заработает, но владелец файлов может отличаться от ожидаемого экспертом.
- **Chrony**: внешний сервер `time.cloudflare.com` захардкожен; stratum 5 у ISP
  гарантируется только при доступности внешнего источника со stratum ≤ 4.
  UDP/123 через nftables/firewalld отдельно не открывается.
- **Яндекс Браузер**: если пакета нет в подключённых репозиториях ALT, скрипт
  только предупредит — RPM ставить вручную.

### Модуль 3 (эксплуатация)

- **`scp` сертификатов может повесить скрипт**: на ISP и HQ-CLI нет ключей
  sshuser, `scp` спросит пароль и подтверждение host key в интерактиве.
  Запускать из консоли, не из CI/крона.
- **Приватный ключ сайта лежит в `/home/sshuser/sites.key`** на HQ-SRV до ручного
  удаления — не забыть `rm` после передачи на ISP (скрипт только напоминает).
- **fail2ban**: если в установленной версии нет действия `nftables-multiport`
  или уже активна штатная jail `sshd` с другими параметрами, `fail2ban-client -t`
  оборвёт скрипт до шага резервного копирования. Проверить
  `ls /etc/fail2ban/action.d/nftables*` и отключить дубль-jail.
- **CUPS**: вставка `Listen 192.168.100.2:631` ищет строку `Listen localhost:631`;
  если в вашем `cupsd.conf` стоит `Port 631`, сетевой доступ не откроется, а
  строка `Allow from 192.168.200.0/28` сознательно не вписывается
  автоматически (только предупреждение). На клиенте `-m everywhere` не сработает,
  если очередь не driverless, — нужен PPD вручную.
- **restic**: ставится версия из p11 без проверки требования материала о возрасте
  выпуска (≤ 18 мес. к экзамену 2027 — эталон 0.16.5); таймер `backup-irpo`
  включается, даже если репозиторий не инициализирован (нет
  `RESTIC_REPO_PASSWORD` или не выполнен шаг HQ-CLI) — служба будет падать по
  расписанию до ручной инициализации. В бэкап не входит `/var/spool/mail`
  (в материале — опционально, при отсутствии каталога).
- **`trust` на HQ-CLI**: утилита может отсутствовать (пакет `p11-kit-trust`),
  скрипт ограничится предупреждением — тогда импорт CA в браузер вручную.
- **Веб-проверка на ISP**: контрольный `curl` по HTTP после финального конфига
  получает 301 (redirect на HTTPS), а не 401 из комментария в выводе — 401
  проверять уже по `https://web.au-team.irpo/` с HQ-CLI.

### Установка (`install.sh`)

- Способ «одной командой» требует **уже установленный curl** на чистой ВМ
  (скрипт ставит curl только после того, как сам скачался). Если curl нет —
  способ 2 из README (git clone).
- Обновление существующего `/opt/demo2027` делает `git checkout <branch>` +
  `pull --ff-only`: локальные правки в `/opt/demo2027` или смена ветки
  окружением `REPO_BRANCH` могут оборвать обновление. Непустой каталог
  `/opt/demo2027` без `.git` тоже уронит `git clone`.
- Доступность `raw.githubusercontent.com` зависит от сети площадки; при её
  блокировке работает только `git clone` с `github.com`.
